# 数据库表说明

本文档根据 `backend/internal/database/schema.go` 中的 `AutoMigrate` 模型整理。当前代码包含 52 张业务表，数据库默认使用 GORM 将模型名转换为 snake_case 表名，例如 `User` 对应 `users`。

## 一、用户与登录

| 模型 / 表 | 说明 |
| --- | --- |
| `User` / `users` | 用户主表，保存用户名、邮箱、角色、状态、密码哈希、最后登录时间，以及 KOL 用户 ID 映射字段。 |
| `AuthSession` / `auth_sessions` | 登录会话，保存用户会话 Token 的哈希和过期时间。 |
| `UserIdentity` / `user_identities` | OAuth 第三方身份绑定，例如 GitHub、Google 账号。 |
| `OAuthState` / `oauth_states` | OAuth 登录过程中的临时状态，用于防 CSRF 和 PKCE 校验。 |
| `EmailVerificationCode` / `email_verification_codes` | 邮箱验证码，只保存验证码哈希、用途、过期时间和使用状态。 |

## 二、AI 渠道与调用记录

| 模型 / 表 | 说明 |
| --- | --- |
| `ModelChannel` / `model_channels` | AI 渠道配置，例如 OpenAI、火山、Gemini 和自定义渠道。保存地址、密钥、并发数和渠道级模型列表。 |
| `ChannelModel` / `channel_models` | 某个渠道下的具体模型，保存模型能力、协议、价格和启用状态。 |
| `ApiCallLog` / `api_call_logs` | AI API 调用日志，记录模型、耗时、Token、状态、错误、上游请求 ID 以及请求响应内容。 |

典型关系：

```text
ModelChannel
    └── ChannelModel
            └── ApiCallLog
```

## 三、AIGC 运营组织与项目

| 模型 / 表 | 说明 |
| --- | --- |
| `AigcDepartment` / `aigc_dept` | 运营团队表，`parent_id` 固定为 `0`，不维护层级结构；通过 `status` 管理启用或禁用，不支持删除。 |
| `AigcProject` / `aigc_project` | 运营项目配置；`project_name` 全局唯一，`project_name_outer` 暂不启用且允许为空，`level` 使用 `1/2` 存储并由前端展示为一级/二级，`project_type` 默认保存为 `默认`；一级项目 `parent_id` 和 `dept_id` 固定为 `0`，所有项目管理用户可见但只有管理员可编辑；二级项目通过 `parent_id`、`first_category_id/name` 归属一级项目，并通过 `dept_id` 归属团队。项目不物理删除，通过 `status` 启用或禁用。 |

`backend/cmd/import-aigc-projects` 可从 `CANVAS_AIGC_MYSQL_DSN` 指定的 `mars_aigc.aigc_secondary_project` 导入未删除的一级分类和二级项目。生产导入必须设置 `CANVAS_DATABASE_DRIVER=postgres` 和目标 PostgreSQL 的 `DATABASE_URL`；命令可重复执行：按项目名称匹配并同步层级、团队、一级项目归属和状态。

## 四、计费与积分

| 模型 / 表 | 说明 |
| --- | --- |
| `ModelPricing` / `model_pricings` | 模型价格配置，按输入 Token、输出 Token、缓存 Token、媒体数量和视频秒数等计价。 |
| `CreditAccount` / `credit_accounts` | 用户积分账户，保存可用积分、冻结积分和版本号。 |
| `CreditLedgerEntry` / `credit_ledger_entries` | 积分流水，只追加不覆盖，记录充值、消费、冻结、退款、赠送和管理员调整；新计费相关流水通过 `aigc_project_id` 记录创作页选择的二级运营项目。 |
| `BillingOrder` / `billing_orders` | 一次 AI 调用对应的计费订单，负责预扣、结算、退款和幂等；新订单通过 `aigc_project_id` 记录创作页选择的二级运营项目。 |
| `RedeemBatch` / `redeem_batches` | 管理员批量生成兑换码的批次。 |
| `RedeemCode` / `redeem_codes` | 单个兑换码，只保存兑换码哈希，不保存明文兑换码。 |

典型关系：

```text
User
 ├── CreditAccount
 ├── CreditLedgerEntry
 └── BillingOrder
       └── ChannelModel
```

## 五、平台配置、统计与技能

| 模型 / 表 | 说明 |
| --- | --- |
| `AdminAuditEvent` / `admin_audit_events` | 管理员操作审计日志，只允许追加，用于追溯管理操作。 |
| `UserDailyActivity` / `user_daily_activities` | 用户每日活跃统计，例如登录次数、任务数、Agent 消息数、资源数。 |
| `SystemSetting` / `system_settings` | 全局系统配置，使用键值形式，值保存在 JSON 中。 |
| `UserOSSSetting` / `user_oss_settings` | 用户自己的 OSS 配置，敏感配置不会通过 API 直接返回。 |
| `UserDailyUploadUsage` / `user_daily_upload_usages` | 用户每日上传容量统计，用于上传配额控制。 |
| `Skill` / `skills` | 系统技能、公共技能或用户技能，保存技能描述、指令、标签和可见性。 |
| `UserSkillState` / `user_skill_states` | 用户与技能的关系，记录是否添加和是否点赞。 |

## 六、资源与素材

| 模型 / 表 | 说明 |
| --- | --- |
| `Resource` / `resources` | 实际文件资源，例如图片、视频、音频和上传文件。保存存储位置、大小、尺寸、媒体类型和状态。 |
| `Asset` / `assets` | 业务素材，例如角色、场景、服装、道具、武器和风格，是素材的逻辑实体。 |
| `ProjectAssetLink` / `project_asset_links` | 项目与素材的多对多关联表。 |
| `ProjectAssetCandidate` / `project_asset_candidates` | 从剧本或项目内容中识别出的素材候选，例如角色、场景和道具。 |
| `AssetVersion` / `asset_versions` | 素材版本，支持草稿、审核、确认和归档。 |
| `AssetRepresentation` / `asset_representations` | 素材版本的具体媒体表现，例如主图、参考图、视频和音频，关联 `Resource`。 |
| `VoiceProfile` / `voice_profiles` | 可复用的声音身份，保存配音模型、音色、语言和声音 key。 |
| `CharacterVoiceBinding` / `character_voice_bindings` | 将某个角色素材版本绑定到声音配置。 |

资源与素材关系：

```text
Asset
 └── AssetVersion
       └── AssetRepresentation
             └── Resource
```

`Resource` 表示文件本身，`Asset` 表示具有业务含义的素材。

## 七、短剧项目

| 模型 / 表 | 说明 |
| --- | --- |
| `Project` / `projects` | 短剧项目聚合根，保存项目名称、类型、画幅、描述、风格、关联二级业务项目 `aigc_project_id` 和版本号。 |
| `StyleProfile` / `style_profiles` | 用户可复用的风格配置，例如视觉风格、色彩、镜头和画面策略。 |
| `ProjectUnit` / `project_units` | 项目的章节或集，支持父子层级。 |
| `CanvasUnitLink` / `canvas_unit_links` | 将画布和短剧章节或单元关联起来。 |
| `Shot` / `shots` | 分镜或镜头，保存描述、顺序、时长和状态。 |
| `ShotAssetReference` / `shot_asset_references` | 镜头引用的素材版本，例如角色、场景和道具。 |

典型关系：

```text
Project
 ├── ProjectUnit
 │     └── Shot
 ├── StyleProfile
 └── ProjectAssetLink
```

## 八、工作流

| 模型 / 表 | 说明 |
| --- | --- |
| `WorkflowTemplateVersion` / `workflow_template_versions` | 工作流模板版本，保存步骤定义 JSON。 |
| `WorkflowInstance` / `workflow_instances` | 某个项目或单元实际运行的一次工作流。 |
| `WorkflowStepInstance` / `workflow_step_instances` | 工作流实例中的具体步骤，保存状态、输入、输出和错误。 |
| `WorkflowStepTask` / `workflow_step_tasks` | 工作流步骤与实际异步任务之间的关联。 |

典型关系：

```text
WorkflowTemplateVersion
          ↓
WorkflowInstance
          ↓
WorkflowStepInstance
          ↓
WorkflowStepTask → Task
```

## 九、画布与分享

| 模型 / 表 | 说明 |
| --- | --- |
| `CanvasProject` / `canvas_projects` | 独立画布文档，保存画布标题、完整画布 JSON 和继承的 `aigc_project_id`。它与短剧 `Project` 是两个概念；画布归属短剧变化时，业务项目关联随短剧同步。 |
| `CanvasShare` / `canvas_shares` | 画布分享链接，保存分享 Token 哈希、加密值、启用状态和过期时间。 |

`CanvasProject.ProjectID` 可以把画布关联到短剧项目，但画布本身也可以独立存在。

## 十、提示词与公告

| 模型 / 表 | 说明 |
| --- | --- |
| `PromptTemplate` / `prompt_templates` | 系统提示词模板，按操作类型和版本管理。 |
| `UserPromptCustomization` / `user_prompt_customizations` | 用户对某类创作操作的提示词定制，不保存完整运行时上下文。 |
| `Announcement` / `announcements` | 系统公告，支持信息、成功、警告和严重等级，以及发布、关闭状态。 |
| `UserAnnouncementRead` / `user_announcement_reads` | 用户是否已读某条公告。 |

## 十一、任务、会话与结果

| 模型 / 表 | 说明 |
| --- | --- |
| `Task` / `tasks` | 异步生成任务主表，记录任务类型、状态、模型、进度、输入、结果、重试、取消和租约信息；`aigc_project_id` 记录创作页生成时选择的运营项目。 |
| `TaskTextDelta` / `task_text_deltas` | 文本流式输出的增量片段，带递增序号和过期时间，用于 SSE 断线恢复。 |
| `Session` / `sessions` | 一次 Agent 或创作会话，保存提示词、画布快照和画布操作记录。 |
| `Message` / `messages` | 会话中的用户、助手和系统消息。 |
| `TaskLog` / `task_logs` | 任务运行日志，例如执行阶段、警告和错误。 |
| `SessionFile` / `session_files` | 会话上传的文件元数据，实际文件路径不会通过 API 返回。 |
| `Result` / `results` | 任务产生的结果，例如图片、视频、音频或文本结果。 |

典型关系：

```text
Session
 ├── Message
 ├── SessionFile
 └── Task
       ├── TaskTextDelta
       ├── TaskLog
       └── Result
```

## 数据库实现注意事项

1. 后端启动时调用 GORM `AutoMigrate`，表结构主要由 Go 模型自动创建。
2. `UserID`、`TaskID`、`ProjectID` 等字段主要是应用层逻辑关联，当前模型没有为所有关系创建显式 PostgreSQL 外键。
3. 很多业务字段使用 JSON 文本保存，例如 `InputJSON`、`PayloadJSON` 和 `DefinitionJSON`，具体结构需要结合对应 service/API 查看。
4. `Resource` 保存文件元数据，不等于实际文件本身；实际文件可能位于 OSS 或本地数据目录。
5. `TaskTextDelta` 是用于流式输出恢复的临时增量，最终内容应以 `Task.ResultJSON` 或 `Task.TextDraft` 为准。
6. `AdminAuditEvent` 和 `CreditLedgerEntry` 属于审计或流水表，原则上不应直接修改历史记录。
7. 媒体资源删除不会自动清理 OSS 远端对象，删除业务记录和删除远端文件是两个不同操作。
